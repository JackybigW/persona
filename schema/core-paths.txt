# Which paths are Persona Core, for the checks that control changes to it (#14916, part of #13430;
# CONTRIBUTING.md "Changing Persona Core", docs/architecture/core-and-modules.md "Guards").
#
# Persona Core has no UI: it is the abilities and interfaces for Agents, sessions, tasks and to-dos (the hub API and the
# data model). The clients' interface code is one default panel built on Core. There are two tiers, plus modules:
#   core    strictly controlled: the core-change check (label + reason) and CODEOWNERS apply, and no module reference.
#           The server core, the clients' HEADLESS code (wire types, the hub client, data models) and the foundation
#           interfaces (module host, switch, guards and gates).
#   panel   the default panel: the clients' interface code. Not under the core-change check, not in CODEOWNERS; only
#           the no-module-reference guard applies (scripts/test/test_core_references_no_module.py).
#   module  module directories: neither tier, free to change.
#
# Read by scripts/test/core_paths.py (`is_core`, `is_panel`, `tier`, `core_files`). Checked by scripts/test/test_core_paths.py:
# the file parses, every explicit path exists (a stale line fails), module directories are never core or panel, sample
# paths classify as expected, and a `headless` path holds no UI import (androidx.compose, SwiftUI, UIKit, AppKit, React,
# .tsx; test files excluded). It feeds scripts/hooks/codeowners.py (the generated block of .github/CODEOWNERS, tier core
# only) and scripts/hooks/core-change-check.py (the merge gate in scripts/hooks/merge-pr.sh, tier core only).
#
# Lines (`#` starts a comment):
#   classified <tier> <kind> <root>...
#                                 every file under the roots whose unit schema/module-classification.txt classifies `core`
#                                 gets the tier (kind: go, web, gradle, apple); a unit it classifies as a module id is a
#                                 module. The classification file is the one list of units, so it is not repeated here.
#                                 The server is tier core; the three clients' interface code is tier panel unless a
#                                 line below lifts it.
#                                   go      server/ and sdk/go/: a file with no classified directory above it (go.mod,
#                                           migrations) is core
#                                   web     web/src/
#                                   gradle  android/: a file belongs to the project with the longest matching directory
#                                   apple   apple/: a file belongs to the nearest classified directory
#   core <path>                   a foundation path named explicitly so it is visible at a glance: a file, a directory
#                                 (and all below it) or a glob with `*`. Tier core. A test-only change in it does not count.
#   headless <path>               client code with no UI (a directory, a file or a glob): tier core. Proven by the test
#                                 above, so a file with a UI import cannot be listed.
#   guard <path>                  tier core, but a test file in it counts too: the path is itself a guard or a gate
#
# Test-only changes do not count as a core change; tests may be added freely. A file is test-only when it is
#   Go     *_test.go, or anything under testdata/
#   web    *.test.ts, *.test.tsx, *.test.js, *.test.mjs, *.spec.*, anything under __tests__/
#   Android  anything under src/test/, src/androidTest/ or src/*Test/ of a project
#   Apple  a path with a directory named *Tests (PersonaTests, PersonaUITests), or a file *Tests.swift / *Test.swift
# unless a `guard` line names the path. Fixtures a test reads sit in these places too (testdata/, test directories).

classified core go server sdk/go
classified panel web web/src
classified panel gradle android
classified panel apple apple
